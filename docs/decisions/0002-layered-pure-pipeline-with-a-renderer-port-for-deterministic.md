# Layered pure pipeline with a renderer port for deterministic PDFs

Status: accepted (generated, pending human review)

## Context

Business documents (letters, reports, certificates) are usually produced by printing HTML in headless Chromium, which is heavy and gives different bytes on every run. Low-level PDF libraries are light but need manual coordinates and line breaking. Template data is also untrusted, so it must never be able to inject document structure or reach prototype properties.

## Decision

Split generation into pure steps: a Mustache-subset template engine with own-property path lookup, size, depth and iteration limits and backslash escaping of structural values at line start; a minimal markup parser; a pure layout function that maps blocks to positioned text operations through an injected FontMetrics; and a PdfRenderer port with a pdf-lib implementation (standard Helvetica fonts, fixed producer and creator, metadata dates, no object streams) and a fake implementation for tests. LaidOutPage carries its own width and height so the renderer needs no page spec. Text is checked against WinAnsi before measuring and drawing, with an opt-in replacement by a question mark.

## Consequences

Layout is fully testable with golden operations and no PDF library, and generated bytes are reproducible for identical input. The scope is deliberately small: only Helvetica and Helvetica-Bold, WinAnsi text, no tables, images, custom fonts or HTML. Data cannot create headings, bullets or page breaks. The cost is a few extra rules to document: structural values get a backslash prefix, U+00A0 and U+00AD are rejected, and page breaks never create empty pages. pdf-lib is the only runtime dependency.
